# 🚀 Clash 客户端全平台配置与进阶使用指南

Clash 是一类常见的规则管理与网络代理客户端，可以通过配置文件、代理节点以及分流规则，对不同网络请求进行分类处理。

对于需要使用不同网络服务、管理多个节点，或者希望进一步了解网络分流原理的用户来说，Clash 是一个值得学习的工具。

本指南将从 **安装、订阅配置、节点选择、规则模式、系统代理、TUN 模式以及常见问题排查** 等方面进行介绍。

除了 Clash，本知识库也会整理 **sing-box、IP 信息查询、DNS 检测、网络测速以及 AI 工具使用相关内容**，方便在遇到网络问题时逐项排查。

> **说明：** 不同 Clash 客户端的界面和功能可能存在差异，本文以常见的现代 Clash 客户端为例。具体操作请以你当前使用的客户端版本为准。

# 一、使用 Clash 前需要准备什么

在开始配置 Clash 之前，通常需要准备以下内容：

### ① Clash 客户端

首先需要根据自己的设备选择合适的客户端。

常见设备包括：

* Windows
* macOS
* Android
* iOS

不同平台的客户端并不完全相同，因此建议根据自己的设备查看对应教程。

### ② 配置文件或订阅地址

如果你的服务商提供订阅功能，通常会提供一个订阅地址。

订阅地址一般用于获取：

* 节点信息
* 代理组
* 路由规则
* DNS 配置
* 其他客户端参数

**请注意：**

订阅地址相当于个人配置凭证，不建议公开发布到 GitHub、论坛或社交平台。

如果订阅地址意外泄露，建议及时重新生成或更新。

# 三、Windows / macOS 配置方法

以下以支持 Mihomo / Clash Meta 核心的现代 Clash 客户端为例。

## 第 1 步：安装客户端

下载与你的操作系统对应的版本。

安装完成后启动客户端。

首次运行时，如果系统出现网络权限提示，请根据自己的需求决定是否允许相关网络访问权限。

---

## 第 2 步：添加订阅

进入客户端的配置或订阅页面。

将服务商提供的订阅地址粘贴进去，然后点击：

**导入 / 添加 / 更新**

不同客户端的按钮名称可能有所不同。

成功后，配置列表中通常会出现一个新的配置文件。

---

## 第 3 步：选择配置

选择刚刚导入的配置文件。

之后进入：

**代理 / Proxies**

页面。

如果配置正常，通常可以看到不同的代理组以及节点列表。

---

## 第 4 步：选择节点

可以根据自己的需求选择不同地区的节点。

例如：

* 香港
* 日本
* 新加坡
* 美国
* 欧洲
* 其他地区

节点的实际延迟会受到网络环境、服务器负载以及距离等因素影响。

因此不要单纯根据节点名称判断速度。

---

## 第 5 步：开启系统代理

如果希望浏览器等支持系统代理的软件使用 Clash，可以打开：

**系统代理 / System Proxy**

开启后，可以访问一个 IP 查询网站确认网络是否发生变化。

# 四、Android 配置方法

Android 用户的具体操作会根据客户端版本有所不同。

添加完成后，点击配置文件进行更新。

如果更新成功，通常可以看到节点和代理组。

根据系统提示完成授权即可。

# 五、Clash 三种常见运行模式

Clash 最重要的功能之一就是根据规则决定不同流量应该如何处理。

常见模式包括：

## 1. Rule｜规则模式

**推荐作为日常使用模式。**

Clash 根据配置文件中的规则判断不同请求。

例如：

```text
国内网站 → DIRECT
海外网站 → PROXY
广告域名 → REJECT
```

实际规则取决于你的配置文件。

规则模式的优势是可以减少不必要的代理流量，同时让不同类型的网络请求按照规则自动处理。

---

## 2. Global｜全局模式

所有符合客户端接管范围的流量统一通过当前代理组。

适合用于：

* 临时测试
* 排查规则问题
* 判断某个网站是否与分流规则有关

不建议在不了解流量情况的情况下长期使用。

---

## 3. Direct｜直连模式

所有流量尽量直接连接，不通过代理节点。

适合用于：

* 暂时关闭代理
* 测试本地网络
* 对比网络环境
* 排查连接问题

---

# 六、Clash 规则与分流

如果想真正理解 Clash，建议学习规则系统。

一个简单的分流逻辑可以理解为：

```text
访问请求
   │
   ▼
匹配规则
   │
   ├── 国内域名 → DIRECT
   │
   ├── 特定服务 → PROXY
   │
   ├── 广告域名 → REJECT
   │
   └── 未匹配 → FINAL
```

常见规则类型包括：

* DOMAIN
* DOMAIN-SUFFIX
* DOMAIN-KEYWORD
* IP-CIDR
* GEOIP
* RULE-SET
* MATCH

如果你希望进一步学习规则，可以查看：

**📚 [Clash 规则配置教程]([Clash 规则教程](https://clashwiki.blog))**

# 七、TUN 模式是什么？

有些应用不会使用系统 HTTP / SOCKS 代理。

这种情况下，即使 Clash 已经开启系统代理，这些应用仍然可能无法正常使用代理配置。

TUN 模式就是为这种场景提供的一种网络接管方式。

简单理解：

> **系统代理主要处理支持代理设置的应用，而 TUN 可以在系统网络层面接管更多类型的流量。**

TUN 模式比较适合：

* 某些不支持系统代理的应用
* 部分开发工具
* 游戏及其他网络程序
* 需要统一网络管理的场景

不过，TUN 模式涉及系统网络设置，建议先了解客户端说明，再根据自己的需求开启。

# 八、节点延迟与网络测试

看到一个节点显示：

```text
30 ms
```

并不代表所有网站实际访问速度都一定很快。

网络体验通常还受到：

* 节点负载
* 带宽
* 路由质量
* 目标服务器
* DNS
* 网络运营商
* 当前时间段

等因素影响。

因此建议综合观察：

**延迟 + 丢包 + 下载速度 + 实际访问体验**

而不是只看 Ping。

# 九、如何检查公网 IP

当你遇到 AI 网站登录、地区识别或者网页访问异常时，可以先检查当前公网 IP。

一个常用的 IP 信息查询网站是：

**[IPinfo](https://ipinfo.io/)**

通常可以查看：

* IP 地址
* Country
* Region
* City
* ASN
* Organization
* 网络运营商等基础信息

> IP 地理位置数据库并非绝对准确，不同数据库之间可能存在差异。因此查询结果更适合作为网络环境参考。

# 十、如何检查 DNS

DNS 负责将域名转换为 IP 地址。

如果出现：

* 网站打不开
* 域名解析失败
* 页面加载异常
* 部分网站可以访问、部分网站无法访问

可以进一步检查 DNS。

常见排查方式：

```text
域名
 ↓
DNS 查询
 ↓
得到 IP
 ↓
建立连接
 ↓
访问网站
```

可以使用 DNS 查询工具检查域名当前解析结果。

---

确认域名可以正常解析。

---

### ④ 检查浏览器

可以尝试：

* 无痕窗口
* 清理缓存
